## 1. 每次开发从这里开始

打开终端，依次执行：

```bash
# 启动本机 MySQL 和 API，等待 API 健康检查通过
/home/smxvjv/Desktop/weixinapp/scripts/local-dev.sh start

# 在微信开发者工具中打开项目
/home/smxvjv/Desktop/weixinapp/scripts/local-dev.sh open
```

启动成功时，终端会返回：

```json
{"code":0,"data":{"status":"ready"},"message":"ok"}
```

微信工具应打开「夏目数码」项目，首页显示测试服务器上的商品。页面默认不访问本机 API；开发或验证本机后端时才需要启动上述服务，并临时修改 `baseUrl`。

也可以双击桌面的「微信开发者工具」快捷方式，在项目列表中打开 `xiamu-digital`。如果列表中没有项目，手动导入目录：

```text

```

**导入仓库根目录，不要只选择里面的 `miniprogram` 文件夹。** 根目录的 `project.config.json` 会指定小程序源码位置。

API 和数据库未设置登录自启。重启电脑或重新登录后，按上述命令启动即可；重复执行 `start` 不会重建或清空数据库。`open` 只负责打开项目，不会自动启动 API。

## 4. 如何看页面、切换身份

1. 打开项目，等待编译完成；需要手动编译时点击微信工具的「编译」或对应的圆形箭头。
2. 顾客端底部有「首页 / 分类 / 成为代理 / 我的」四个入口。
3. 默认连测试服务器时，员工用手机号和验证码登录，没有模拟身份入口。要切换模拟身份，先把 `develop` 的 `useMock` 临时改为 `true` 并重新编译（不要提交），再到「我的 → 开发调试 / 切换模拟身份」选择身份；员工登录页也支持选择模拟员工角色。
4. 可切换顾客、同行、代理、老板、店长、采购、库管、销售、工程师、财务，检查相应页面和字段权限。
5. 验证员工经营端时，可选择「老板」后进入经营入口，再检查库存、采购、收银、维修、借还等页面。

这些角色切换只用于模拟模式，不会创建正式员工账号，也不代表真实短信或微信身份验证通过。模拟业务数据保存在内存中，重新编译会重置。要做角色业务测试，见 `docs/role-tests/README.md`。

### 页面数据和 MySQL 数据为什么不一样

当前 `/home/smxvjv/Desktop/weixinapp/miniprogram/config/index.js` 中开发环境配置为：

```javascript
develop: { baseUrl: '<测试服务器地址>/api/v1', useMock: false }
```

此时请求发到测试服务器，写入的是服务器上的数据库，不是本机 MySQL。改成 `useMock: true` 后，请求由小程序的 mock 模块处理，页面显示商品、模拟销售成功，均不能据此判断 MySQL 中已产生相同记录。

| 操作 | 当前使用的数据 |
| --- | --- |
| 默认模拟器页面 | 测试服务器 MySQL 与 COS |
| `useMock: true` 时的页面与模拟角色操作 | 小程序 mock 内存数据 |
| 本机 API 健康检查 | 本机 API 连接本机 MySQL 执行检查 |
| 服务端集成测试 | 真实 HTTP、专用测试库及测试文件 |
| 正式微信/SMS 外部调用 | 当前未配置，测试服务器用开发固定验证码登录，不能作为已联调能力使用 |

## 5. 改代码后怎么生效

### 修改小程序

主要代码位于 `/home/smxvjv/Desktop/weixinapp/miniprogram`。保存代码后等待工具检测变更，再按需要重新编译。无需为小程序源码运行根目录的 `npm install`；当前小程序为原生项目，后端依赖单独放在 `server` 中。

根目录的 `project.config.json` 已排除 `.local/`、`server/node_modules/` 和 `.git/` 的监听，避免把数据库文件和后端依赖当成小程序源码扫描。不要把服务端密钥或数据库数据复制进 `miniprogram`。

### 修改 API 或服务端配置

API 没有开启代码热重载。修改 `/home/smxvjv/Desktop/weixinapp/server/src` 或 `server/.env` 后执行：

```bash
/home/smxvjv/Desktop/weixinapp/scripts/local-dev.sh restart
```

服务已经由 systemd 管理时，不要再同时运行 `npm --prefix server start`，否则第二个进程可能因 3000 端口被占用而启动失败。

### 安装后端依赖

正常使用无需重复安装。锁文件或依赖发生变更时，使用：

```bash
export PATH="/home/smxvjv/.local/bin:$PATH"
npm --prefix /home/smxvjv/Desktop/weixinapp/server ci
/home/smxvjv/Desktop/weixinapp/scripts/local-dev.sh restart
```

### 应用新增数据库迁移

确认数据库已启动，并先做好业务数据备份，再执行：

```bash
export PATH="/home/smxvjv/.local/bin:$PATH"
npm --prefix /home/smxvjv/Desktop/weixinapp/server run migrate
npm --prefix /home/smxvjv/Desktop/weixinapp/server run db:grants
/home/smxvjv/Desktop/weixinapp/scripts/local-dev.sh restart
```

`db:grants` 为新增表补齐本机账号权限，仅用于项目专属实例。此处不包含迁移失败后的自动回滚或生产数据库运维流程。

**本机不要运行 `npm --prefix server run db:start`。** 仓库原脚本依赖 macOS Homebrew；Ubuntu 的数据库启动入口是 `local-dev.sh` 管理的 Docker 容器。

## 7. 服务、安装位置和重要文件

### 服务结构

```text
微信模拟器 ── 默认 useMock: false ── 测试服务器（API、MySQL、COS）
        └── 临时改 useMock: true ── 小程序 mock

本机 API 127.0.0.1:3000 ── 运行账号 ── MySQL 127.0.0.1:3307
        │                                  │
        └── .local/files/                  └── .local/mysql/
```

API 服务 `xiamu-api.service` 依赖 `xiamu-mysql.service`，启动前会等待数据库就绪。MySQL 容器名称为 `xiamu-wechat-mysql`；使用 host 网络，但 MySQL 本身只绑定 `127.0.0.1`，没有对外开放数据库。

为适配本机内存，MySQL buffer pool 为 64MiB、容器内存上限为 1GiB；API 内存上限为 384MiB。MySQL 的 `performance_schema` 保持开启，已有并发测试依赖其中的锁等待信息。

## 8. 已知问题和处理方式

| 现象 | 优先检查和处理 |
| --- | --- |
| 模拟器一直停在欢迎页，项目初始化不结束 | 使用桌面快捷方式、`local-dev.sh open` 或用户目录包装器启动。它们配置了轮询监听；直接运行安装目录的 Electron 会绕过包装器。首次编译仍需等待一段时间。 |
| 日志出现 `inotify_init() failed` 或 `Too many open files` | 本机部署时发现每用户 inotify 实例额度耗尽；包装器已设置 `CHOKIDAR_USEPOLLING=1`、`CHOKIDAR_INTERVAL=1000`。不要通过删除项目数据来处理。 |
| `start` 失败或 API 不可访问 | 先执行 `status`，再看 `logs` 和 `.local/mysql.log`。确认 Docker 服务可用、项目容器存在、3307/3000 未被其他程序占用。 |
| 运行状态里显示 `disabled` | 表示未启用登录自启；是否正在运行应看 `active`。当前选择手动启动以减少后台占用。 |
| 后端提示 3000 端口已占用 | 检查是否手动启动了第二个 API。保留用户服务管理的实例，不要随意终止未知服务。 |
| `node` 或 `npm` 找不到 | 执行 `export PATH="/home/smxvjv/.local/bin:$PATH"`；`local-dev.sh` 自带该设置。 |
| 页面能操作，本机数据库没有变化 | 页面默认写测试服务器，mock 模式写内存，都不进本机 MySQL。检查 `useMock` 和 `baseUrl`，不能通过反复重启数据库解决。 |
| 真实微信登录、发短信返回配置缺失或 503 | 对应外部服务尚未配置；这是当前环境限制。员工登录可在非生产环境设置 `OTP_DEV_CODE`，顾客的微信静默登录仍需 `WX_APP_SECRET`。 |
| 扫码预览或 AppID 提示没有权限 | 需要对应小程序管理员添加当前微信号为开发者，并核对平台权限；本机导入成功不等于获得账号权限。 |
| 代码保存后页面没变化 | 等待轮询检测，手动编译，确认打开的项目目录正确；后端代码修改则重启 API。 |
| `git clone` 后换一台电脑无法直接启动 | Node.js、微信工具、Docker 容器、systemd 用户服务及被忽略的本地配置不随 Git 同步，需要重新部署。 |

微信工具是社区 Linux 移植版。当前模拟器已经验证，真机调试、最新平台能力和外部服务仍需按实际项目验证；不要把现有测试结果作为所有功能均已交付的结论。

## 10. 数据备份、换机与后续接手

当前没有配置自动备份，也没有完成恢复演练。如果准备变更数据库或搬迁环境，应先安排备份。

本机冷备份的操作原则：

1. 使用 `local-dev.sh stop` 停止 API 和数据库，确认数据库容器已停止。
2. 将项目的 `.local/`、服务端环境配置及源码一同复制到受限的备份位置；备份包含敏感凭据，不上传公共仓库。
3. 另行保存本节列出的两个 systemd 用户服务、微信工具启动包装器，以及固定镜像 digest。它们不在 Git 仓库中。
4. 完成复制后使用 `local-dev.sh start` 恢复运行，检查健康接口。

运行中的 MySQL 数据目录不应直接当成一致性备份复制。物理数据文件的恢复还需匹配 MySQL 版本、目录挂载和权限；新机器不能只复制源码就宣称恢复完成。备份工具、保留周期及恢复演练后续另行落实。

本机部署相关 Git 改动尚未提交或推送，交接时可通过 `git status` 查看。包括 `project.config.json` 的监听排除配置、`scripts/local-dev.sh` 和本机说明文档。后续更新源码前先检查并保留本地改动，不要用强制重置覆盖它们。

- `docs/ACCEPTANCE.md`：页面走查、已验证范围和剩余事项。
