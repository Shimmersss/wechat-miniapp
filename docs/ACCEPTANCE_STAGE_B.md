# 夏目数码 · 阶段 B 验收说明（维修 / 借还 / 分渠道分享）

更新时间：2026-11-04。对应 main 分支 `3d0216f`。复选框留给人工验收，不是已通过标记。阶段 A、C 及权限底线见 `ACCEPTANCE.md` 和 `FEATURES_AND_TESTS.md`。

## 一、验收前准备

- 微信开发者工具导入仓库根目录，默认 `useMock: true`，不需要后端。“我的 → 开发调试 / 切换模拟身份”切换身份。
- mock 数据在内存里，**重新编译会清空本轮新建的单据**，一条流程尽量一次走完。
- 想看数据真实落库，把 `miniprogram/config/index.js` 的 `useMock` 改为 `false`，先 `npm --prefix server start`（数据库未启动先 `npm --prefix server run db:start`）。验收完记得改回。
- 本轮用到的身份：**老板**（全权限）、**维修工程师**、**销售**、**顾客**、**代理**。
- 拍照、扫码、相册保存、转发在模拟器里只能走通流程，结果以真机为准，见第五节。

## 二、维修

入口：工作台 → 维修看板；本店设备送修从“库存 → 设备详情 → 送修”进入。

### 2.1 外部送修全流程（老板）

| ✓ | 操作 | 应看到 |
|---|---|---|
| [ ] | 看板“＋ 维修开单” → 不填联系人/电话/型号直接保存 | 提示缺项，不能保存；电话必须 11 位 |
| [ ] | 填齐联系人、电话、型号、故障，传 1～2 张外观照片，分派一名工程师 → 保存 | 显示“维修单已保存”，可“查看维修单”；看板“待检测”列最上方出现这张单 |
| [ ] | 页面提示文字 | 写明“外部送修机仅建维修档案，不进入门店可售库存”和“不记录开机密码” |
| [ ] | 详情 → 填检测结果和拟维修方案 → 保存 | 状态进入检测/待确认；时间线多一条记录 |
| [ ] | 填维修报价（如 260）→ 记录报价 | 状态“待顾客确认”；提示“新报价将使之前的确认失效” |
| [ ] | 不勾“已核对并获得本次确认”直接记录确认 | 被拦下 |
| [ ] | 勾选后记录确认 → 开始维修 | 状态“维修中” |
| [ ] | **再改一次报价**（如 300） | 旧确认失效，必须对新报价重新确认才能继续 |
| [ ] | 标记“等待配件” → 尝试完工 | 提示先确认配件齐备并关闭待配件标记 |
| [ ] | 关闭待配件 → 填维修结果与复测结论 → 完工 | 状态“待取机” |
| [ ] | 未收款直接取机 | 提示“请先结清当前维修报价” |
| [ ] | 收支登记 → 登记收款 300（选现金/微信等），不勾“已实际办理” | 被拦下；页面写明“不会发起微信/支付宝扣款或退款” |
| [ ] | 勾选后登记收款 → 取机：不填交接人或不传凭证 | 缺项不能完成 |
| [ ] | 填交接人、上传取机凭证、质保天数（0～3650）→ 完成 | 状态“已完成”；时间线完整，从开单到取机每步有人员和时间 |
| [ ] | 登记退款，金额超过已收净额 | 被拒 |

### 2.2 本店设备送修（老板）

| ✓ | 操作 | 应看到 |
|---|---|---|
| [ ] | 库存 → 选一台在库设备 → 送修 | 开单页直接带出这台设备（型号、存储、脱敏串码），提示“送修会关闭分享并退出可售库存” |
| [ ] | 保存后回到库存 | 该设备状态“维修中”，不能加入收银、不能分享 |
| [ ] | 按 2.1 走到完工 | 设备回到“待复检”，**不会**直接回到在库可售 |
| [ ] | 库存详情复检通过 | 设备回到在库；分享开关不会自动打开 |
| [ ] | 另开一张本店送修单后取消 | 取消前须退清对客收款；设备同样进入“待复检” |

### 2.3 配件（老板 → 工程师）

| ✓ | 操作 | 应看到 |
|---|---|---|
| [ ] | 看板“配件库存” → 新增配件（名称、唯一 SKU、单位） | 保存成功；重复 SKU 被拒 |
| [ ] | 采购入库：数量 10、单价 35 | 库存 10；“查看流水”有入库记录 |
| [ ] | 维修单详情 → 领用配件 2 个 | 配件库存剩 8；单据“配件领退”里有记录 |
| [ ] | 领用超过库存数量 | 被拒，不能透支 |
| [ ] | 退料 1 个 → 再退超过剩余领用数（如 5） | 第一次成功；第二次提示“退料数量不能超过原领用剩余数量” |
| [ ] | 切**维修工程师**看配件库存 | 能看到数量，看不到采购单价/成本 |

### 2.4 权限与看板

| ✓ | 操作 | 应看到 |
|---|---|---|
| [ ] | 切**维修工程师**打开看板 | 只能处理分派给自己的单；不能报价、不能收退款、不能分派 |
| [ ] | 切**销售**进入维修相关页面 | 按权限拦截或只读，看不到配件成本 |
| [ ] | 看板搜索：单号 / 型号 / 联系人 | 能查到；勾“仅看待配件”“仅看超期未完成”筛选正确 |
| [ ] | 工作台维修待办 → 点进去 | 跳到看板并带上对应筛选；**今天到期的不算超期**，已完成/已取消不算超期 |
| [ ] | 经营统计 → 维修经营 | 收入、配件、费用、本店维修成本分列显示 |

## 三、出借 / 借入

入口：工作台 → 出借借入；或库存设备详情 → “出借给同行”。mock 预置了一张已逾期的出借单（同行王店长，iPhone 17 Pro）。

| ✓ | 操作 | 应看到 |
|---|---|---|
| [ ] | 列表 → 状态筛选“已逾期” | 预置单显示且标红 |
| [ ] | “出借给同行” → 从库存选择（多选 2 台）/ 扫码 | 只能选在库的自有设备；借入设备、维修中、已售设备选不了 |
| [ ] | 不填对方、电话、应归还日期就保存 | 被拦下；日期不能选今天以前 |
| [ ] | 填齐，写交接说明，传交接照片 → 确认出借 | 页面**没有**押金、逾期费、赔偿栏；保存后两台设备变“出借中”并关闭分享 |
| [ ] | 库存 → 这台设备详情 | 显示关联借还单，可点进去 |
| [ ] | 借还单详情 → 登记归还：只勾 1 台，不填结论或不传照片 | 缺项不能提交 |
| [ ] | 填外观与功能结论、传照片 → 确认归还 | 这 1 台进入“待复检”；单据仍显示 1 台待归还 |
| [ ] | 归还第 2 台 | 单据状态“归还待复检” |
| [ ] | 未复检直接点“完结” | 被拒并提示等待库管复检 |
| [ ] | 点“去复检” → 库存详情复检通过 → **在库存详情页**仍能看到借还单入口 → 回到借还单完结 | 完结成功；设备回到在库，分享不自动打开 |
| [ ] | 库存里一台**在库自有设备**详情 →“出借给同行” | 跳到出借表单，这台设备已预选好 |
| [ ] | “从同行借入” → 选型号、填 IMEI1（可选成色、说明）→ 确认借入 | 设备显示“借入在库”，不能加入收银、不能分享；它的详情页**没有**出借按钮 |
| [ ] | 借入单登记归还 | 直接冲销，单据“已完结”，不需要复检 |
| [ ] | 工作台待办“借还已逾期 / 出借归还待复检” | 数量与列表筛选结果一致 |
| [ ] | 切**销售**打开设备详情 | 不显示借还单信息；进借还页面被拦 |

## 四、分渠道分享与海报

入口：工作台 → 分享；顾客端商品详情底部“海报 / 转发”。

| ✓ | 操作 | 应看到 |
|---|---|---|
| [ ] | 分享页 → 查找现货 → 加入 1 台 → 生成 | 页面说明“分享价格由服务端决定”；有预览、复制文案、转发、分享海报 |
| [ ] | 多选加入 3 台生成合集 | 合集里的设备都在；最多 50 台 |
| [ ] | 尝试分享维修中 / 出借中 / 已售设备，或没开该渠道分享开关的设备 | 生成被拒，提示不可对外分享 |
| [ ] | 复制顾客渠道文案粘贴出来看 | 不含成本、同行价、完整 IMEI |
| [ ] | 分享页切到“同行”渠道生成，切同行身份打开；再用顾客渠道链接以顾客身份打开 | 同行链接显示同行价；顾客链接只显示零售价 |
| [ ] | 对已分享的设备**改价**，或下架，或点“撤销本链接”后再打开旧链接 | 提示链接失效，需要重新生成 |
| [ ] | 打开分享海报 | 先显示“正在核验分享资料…”；没有正式小程序码时明确提示缺配置，**不显示假二维码** |
| [ ] | 海报页“保存海报”，拒绝相册权限 | 出现“打开相册权限设置”入口，不卡死 |
| [ ] | 分享页底部说明 | 写明代理分享由代理在代理中心自己生成加价，门店只需在库存开“允许代理转发” |

## 五、本次验不了、需真机或正式环境的

| 项目 | 原因 |
|---|---|
| 维修外观照片、内部凭证、交接照片的拍照与上传 | 模拟器只能选本地图片 |
| 扫码选机（借还、分享、库存） | 需要真机摄像头 |
| 海报上的小程序码、相册保存、发给好友 | 需要正式 AppID、服务器生成小程序码 |
| 分享链接转发给真实微信好友后打开 | 需要合法域名与真机 |
