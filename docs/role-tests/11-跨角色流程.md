# 11 跨角色流程

每条流程由多个角色接力完成，**按编号顺序执行**，中途不要重新编译。切换身份后，从该身份的正常入口进入页面，不要靠页面缓存判断结果。

记号：`[顾客]` 表示这一步切到该身份操作。

## 顾客成交

### FLOW-01 咨询 → 跟进 → 成交（t31）

1. `[顾客]` t31 详情 → 咨询这台 → 填内容和手机号提交。
2. `[销售]` 顾客跟进 → 打开这条（待跟进） → 选「已联系」→ 填写内部说明并保存。 📷
3. `[销售]` 点「按当前库存价格开单」→ 收银页带入 t31、顾客电话，顶部提示「已关联顾客意向」→ 确认已收款并出库。 📷
4. `[销售]` 回意向详情，有「查看关联销售单」，可跳转。
5. `[顾客]` 我的记录中这条已结束；首页搜不到 t31；直接打开提示已下架。
6. `[老板]` t31 已售，流水 在库可售 → 已售；工作台待跟进数量减少；报表销售额增加 ¥7,249。

### FLOW-02 预约 → 确认 → 到店成交（t32）

1. `[顾客]` t32 → 预约到店，选明天、时段，提交。
2. `[销售]` 打开预约 → 选「已确认预约」保存。
3. `[顾客]` 记录显示已确认预约。 📷
4. `[销售]` 按当前库存价格开单 → 成交 ¥7,249。
5. `[顾客]` 预约状态变「已完成」。

### FLOW-03 意向取消不影响库存（t33）

1. `[顾客]` t33 咨询并提交，再预约并提交。
2. `[顾客]` 取消预约，填原因。
3. `[销售]` 把咨询改为「已结束」，填说明。
4. 两条记录都结束，**没有**开单入口；`[顾客]` t33 仍在售，价格不变。

### FLOW-04 同行意向按批发价成交（t34）

1. `[同行]` t34 → 咨询这台，提交意向。
2. `[销售]` 打开意向，来源为同行，能看到同行价 → 按当前库存价格开单，提示「意向价不锁价」。 📷
3. 打开「按批发价成交」，合计 ¥5,400 → 成交。
4. `[同行]` 记录已结束。
5. `[老板]` 销售单渠道为批发，毛利按批发价计算：¥5,400 − ¥5,000 = ¥400。

## 退款与复检

### FLOW-05 退货 → 复检 → 重新上架 → 再次销售（t35）

1. `[销售]` 零售开单 t35，¥5,399。
2. `[财务]` 销售详情 → 登记退款 / 退货 → 退货入复检，选 t35，金额留空（默认全额）→ 填原因保存。 📷
3. 销售单「已退货」，累计退款 ¥5,399，净实收 ¥0；t35 复检待入库，分享开关全关。
4. `[顾客]` 看不到 t35。
5. `[销售]` 输入 t35 开单，提示「未找到可售设备」。
6. `[库管]` t35 → 填写库存复检 → 通过。 📷
7. `[老板]` t35 在库可售，开关仍全关；打开“展示在店铺”。
8. `[顾客]` 看到 t35。
9. `[销售]` 再次开单成功，生成第二张销售单；两张单各自独立，历史单金额不变。

### FLOW-06 差价退款后再退货（t36）

1. `[销售]` 零售开单 t36，¥5,399。
2. `[财务]` 仅退差价，填 200，填原因。 📷 状态「部分退款」，净实收 ¥5,199，t36 仍已售。
3. `[财务]` 再次退款，选退货入复检，金额留空。
4. 状态「已退货」，累计退款 ¥5,399（不是 ¥5,599），净实收 ¥0，t36 复检待入库。

### FLOW-07 一单两台只退一台（t53、t54）

1. `[财务]` 打开李女士的单 → 退货入复检，只选 t53。
2. 状态「部分退款」，累计退款 ¥4,499，净实收 ¥4,499，毛利 ¥599；t53 复检待入库，t54 仍已售。
3. 再次打开退款，只能选 t54。

### FLOW-08 复检未通过（t64）

1. `[库管]` t64 → 填写库存复检 → 未通过，填说明。 📷
2. t64 仍在复检待入库，不能销售；流水或检查记录保留本次结论；`[销售]` 开单提示「未找到可售设备」。

## 维修

### FLOW-09 本店机送修（t37）

1. `[工程师]` 库存 t37 详情 → 本店设备送修 → 填故障保存。t37 变维修中，开关全关。
2. `[顾客]` 看不到 t37；`[销售]` 不能开单。
3. `[工程师]` 转为检测中 → 填检测结果。
4. `[店长]` 打开单 → 维修报价 0（本店机）。
5. `[工程师]` 直接转维修中，提示「不允许跨节点」或没有该按钮；先转待顾客确认。
6. `[店长]` 记录报价确认。工程师做这一步应被拒绝。
7. `[工程师]` 转维修中 → 领用配件 `P-BAT-16` 99 件，提示「配件库存不足」；再领 1 件成功。 📷
8. `[工程师]` 转待取机：结果留空被拦截，「请确认配件齐备并填写结果」；填结果成功。
9. `[工程师]` 转已完成：取机人留空被拦截；填交接人和凭证成功。
10. t37 变复检待入库（不是直接在库可售）。 `[库管]` 复检通过。
11. `[老板]` 销售成本不受影响；配件库存变 9 件；报表维修数据更新。

### FLOW-10 店外机完整维修

1. `[店长]` 维修开单：iPhone 12、顾客周女士、`13855550001`、IMEI 用 N12、故障「屏幕碎裂」，分派小周。

3. `[老板]` 维修报价 500。
4. `[工程师]` 转待顾客确认。
5. `[老板]` 改报价 450，页面提示新报价使之前的确认失效，状态仍是待顾客确认。`[工程师]` 按新报价记录报价确认。 📷
6. `[工程师]` 转维修中，领用 `P-SCREEN-17P` 1 件，再退料 1 件，再领 1 件。
7. `[财务]` 登记收款 ¥200；维修未结清时 `[工程师]` 不能转已完成。
8. `[工程师]` 转待取机。
9. `[财务]` 再登记 ¥250，已收 ¥450。
10. `[工程师]` 转已完成：取机人周女士、上传凭证、质保 90 天。 📷
11. `[老板]` 列表显示已完成；配件 `P-SCREEN-17P` 余 4 件；维修毛利 = 450 − 800 = −¥350，负数显示清楚。

## 借还

### FLOW-12 出借 → 归还 → 复检 → 完结（t38）

1. `[库管]` 出借给同行 → 从库存选择 t38 → 填对方、电话、到期日、交接说明、交接照片，确认出借。 📷
2. t38 变出借中；`[顾客]` 看不到；`[销售]` 不能开单。
3. `[库管]` 单据 → 登记归还：不勾设备提交，提示「请勾选本次归还的设备」；勾选但不填结论和照片，被拦截；填写后确认归还。
4. 单据显示归还待复检，只有「去复检」，没有「完结」；首页待办「出借归还待复检（台）」+1。
5. `[库管]` 点「去复检」→ 复检通过。
6. 回单据点「完结」，填说明。 📷 单据已完结；待办减少。
7. 全程没有押金、逾期费、赔偿输入项。

### FLOW-13 借入 → 归还（借入设备 IMEI `359999000009019`）

1. `[库管]` 库存筛选「借入在库」找到设备，详情没有出借、送修、加入收银单按钮。 📷
2. `[销售]` 不能开单。
3. `[库管]` 借入单 → 登记归还 → 确认。
4. 设备变已归还，单据完结，不产生采购成本或销售收入。
