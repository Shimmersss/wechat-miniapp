## 二、测试分两轮

| 轮次 | 环境 | 内容 | 费用 |
|---|---|---|---|
| 第一轮 | 本地 mock（假数据） | 按 [`role-tests/`](role-tests/README.md) 的用例逐个角色走完业务和界面 | 不消耗云资源 |
| 第二轮 | 云开发测试环境（真实后端） | 按本文第五节，重点看登录、权限、数据是否真的保存、上传下载 | **消耗资源点，见第四节** |

先做第一轮，把界面和业务逻辑问题尽量在 mock 里发现；第二轮只验证"连上真实后端后是否还对"，不要在云端重复把所有用例跑一遍。

`docs/test-cases/` 是另一套旧用例，本次不用。

## 三、准备环境

1. **申请权限**：请开发负责人在微信公众平台把你的微信号加为该小程序的**开发者**，并私下告诉你 AppID。
2. 安装微信开发者工具，导入仓库根目录。
3. 在仓库根目录执行下面这条命令，设置 AppID（只写进本机被忽略的文件）：

   ```bash
   ./scripts/appid.sh 你拿到的AppID
   ```

4. 编译。开发版默认连云开发测试环境（`miniprogram/config/index.js` 的 `develop` 段里 `useCloud: true`）。
5. **第一轮 mock**：把 `develop` 段的 `useMock` 改为 `true` 再编译，按 [`role-tests/README.md`](role-tests/README.md) 的"准备环境"操作。测完改回 `false`。**这项改动不要提交。**
6. **真机测试**：在开发者工具点"预览"，用自己的微信扫码。进入小程序后，点微信右上角"…"→"开发调试"→**打开调试**再重进。这是微信菜单里的开关，不是「我的」页里只在 mock 模式出现的"开发调试"。正式的上传、下载合法域名还没配置，不开调试时，真机上的拍照上传、导出下载可能会失败。这不算缺陷，但记录时要注明是否开了调试。

## 四、云端测试的注意事项（重要）

- **资源点有限**：测试环境是体验版，每月 3000 资源点（本周期到 12-09）。2026-11-10 已用约 1550，剩下约 1450 要撑到月底。
  - 资源点用完后**所有接口都会失败**，报错可能显示 410 或"余额不足"。遇到这种情况立即停止测试，通知开发负责人，不要反复重试。
  - 大批量操作尽量少做，例如反复导出报表、一次上传很多视频、短时间内大量刷新。
- **不要运行 `scripts/verify-cloud-*.js`、`scripts/run-cloud-maintenance.js` 等脚本**。它们是开发验证用的，会直接写真实数据并大量消耗资源点。
- **测试环境里只有测试数据**，包括开发验证留下的隔离数据，看到奇怪的商品或单据属正常。第 6 步导入正式数据前，这些数据可能会被清空。
- **不要停用或解绑开发负责人的账号**，也不要停用唯一的老板账号。
- 每天北京时间 02:00 后会自动备份一次，你的测试数据也会被备份，不影响测试。

## 五、云端账号怎么获得

| 身份 | 怎么得到 | 说明 |
|---|---|---|
| 顾客 | 打开小程序即是顾客 | 云开发自动识别微信身份，不用登录 |
| 员工（老板、店长、采购、库管、销售、维修工程师、财务） | 老板在「员工管理」新增员工（填你的手机号和角色）→ 你在员工登录页输入手机号和**开发固定验证码** | 固定验证码由开发负责人私下给你。首次登录会把该员工绑定到你的微信 |
| 代理 | 用顾客身份在「成为代理」提交申请 → 老板在「代理审核与管理」里通过 | 通过时会设置加价上限 |
| 同行 | 目前**没有界面可开通** | 需要开发负责人在数据库里设置。没设置就跳过云端同行用例，只在 mock 里测 |

切换员工角色的规则：

- 一个微信只能绑定一个员工账号。要换角色时，请老板在「员工管理」里改你的角色。改完后，你下一次操作就按新角色生效，不用重新登录。
- 自己不能改自己的角色、不能停用或解绑自己。这是规则，不是缺陷。
- 想同时拿到两个员工身份，需要第二个微信号。也可以请老板先"解绑微信"，你再用另一个手机号登录。

真实短信验证码在测试期间**已关闭**，登录只用固定码，不测短信。

## 六、第二轮（云端）必测清单

每一项都按"操作 → 预期 → 实际"记录。数字类的预期以页面显示和你自己的操作为准，不要套用 mock 用例里的基线数字。

### 1. 登录与会话
- [ ] 员工手机号输错、验证码输错，都有明确提示，不会进入工作台
- [ ] 正确登录后进入员工经营台；退出后再进员工页面，会被带回登录页
- [ ] 老板停用某员工后，该员工下一次操作立即失效、回到登录页；恢复后可以重新登录
- [ ] 顾客、代理直接打开员工页面，会被拦下

### 2. 字段与价格可见性（最重要）
- [ ] 顾客端只显示零售价和打码串码，看不到同行价、成本、供应商、内部备注
- [ ] 销售看不到成本和毛利，显示为「无权限查看」
- [ ] 老板在「角色与字段权限」里修改某角色的可见字段后，该角色马上看到相应变化
- [ ] 代理只能在上限内提交加价，代理看到的顾客信息是脱敏的；销售看不到代理加了多少

### 3. 库存主链路（老板或对应角色接力）
- [ ] 供应商 → 采购单 → 到货验收 → 单台入库（拍实拍图）→ 改价 → 开启店铺展示
- [ ] 顾客在首页、分类、搜索中都能找到该设备，详情页图片正常
- [ ] 顾客咨询、预约 → 员工在后台看到并跟进 → 顾客在"我的记录"里看到状态变化
- [ ] 收银开单（可上传收款凭证）→ 销售记录可查 → 退款（必须填原因）→ 设备状态和库存流水正确
- [ ] 批量入库、复检、手动出库、盘点（差异只记录不改库存）

### 4. 其他业务
- [ ] 维修：开单拍照 → 报价 → 领料、退料 → 状态推进 → 收款、退款 → 取机
- [ ] 借还：借出 → 逾期提醒 → 逐台归还 → 复检后完结
- [ ] 代理：申请 → 审核 → 加价分享 → 顾客通过代理链接下单（锁库 30 分钟）→ 收银 → 收益 → 逐单标记已转账（需填原因）→ 退款后收益冲回
- [ ] 分享：员工选设备分享、合集分享；海报页提示暂无法生成可扫码海报（预期，见第七节）
- [ ] 经营统计：趋势、拆分、库龄、代理对账有数据，且和自己的操作对得上
- [ ] 报表导出：必须填原因；能下载并打开 CSV；销售没有导出入口
- [ ] 审计日志：上面的敏感操作（改价、退款、权限变更、导出、转账）都留了记录，且显示了原因
- [ ] 员工管理与角色权限：新增、改角色、停用、恢复、解绑；经理不能改老板

### 5. 界面
- [ ] 浅色、深色、零售绿三套主题下，上面走过的页面没有看不清的文字、错位或溢出（标准见 [`role-tests/12-界面检查标准.md`](role-tests/12-界面检查标准.md)）
- [ ] 任何页面都不应出现"该功能尚未迁移到云开发"。出现就是缺陷，记下页面和操作

## 八、问题怎么记录

报告放在 `docs/role-tests/results/<日期>/`，截图放同目录（截图不进版本库）。每个问题一条：

```markdown
### BUG-001 一句话描述
- 级别：P0（数据错或越权）/ P1（主流程走不通）/ P2（次要功能或明显界面问题）/ P3（小瑕疵）
- 环境：mock / 云端（真机是否开调试）
- 身份与主题：销售 / 深色
- 页面：packages/staff/pos/index
- 时间：2026-11-12 14:35（云端问题必须写，开发要据此查日志）
- 步骤：1. … 2. …
- 预期：…
- 实际：…（附截图、报错原文）
```

以下情况请当天告诉开发负责人，不要等整轮结束：

- 任何**越权或泄露**：看到不该看的价格、成本或完整串码，或进了不该进的页面；
- 任何**数据错误**：金额、库存状态、收益算错；
- 资源点耗尽。
