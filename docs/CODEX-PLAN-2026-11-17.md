## 1. 开发版也走 HTTPS 网关，只维护一套部署

### 现状

- `miniprogram/config/index.js`：开发版和体验版都会读 `config/cloud.local.js` 里的 `httpBaseUrl`。读到了就走网关（`request.js:138` 的 `wx.request` 分支），读不到时开发版会退回 `wx.cloud.callFunction`，连小程序默认关联的环境。
- `cloud.local.js` 已被 `.gitignore` 忽略，由 `scripts/configure-cloud-preview.js` 生成，这个脚本默认读 `.local/cloudbase/single-env-gateway.json`。
- 2026-11-17 实测：默认环境 `cloud1-…` 里只有 `shop` 一个函数，其他函数都不存在。所以没有 `cloud.local.js` 的机器上，开发版大部分接口都报“网络异常”（真实错误是 `-505005 FUNCTIONS_NOT_FOUND`）。

### 要做

1. **开发版强制走网关。** 删掉开发版的 `wx.cloud.callFunction` 回退分支，开发版和体验版走同一条路：
   - `request.js` 的 `callCloud`：`cloudHttpBaseUrl` 为空时，开发版也直接报错（不再只有 `trial` 报错），提示“未配置云开发网关，请运行 node scripts/configure-cloud-preview.js <网关域名>”。
   - `config/index.js`：删除 `cloudEnv` / `xm_cloud_env` 相关代码和注释。开发版的 `cloudHttpBaseUrl` 只认 `cloud.local.js`。是否保留 `xm_cloud_http_base` 这个缓存覆盖（方便临时指向别的网关）由实现者决定，保留的话写清注释。
   - 上传 `uploadCloud` 已经走 `/files/upload-intent` 接口，不依赖 `wx.cloud`。小程序里只有 `request.js` 用到 `wx.cloud`（`config/index.js` 里只是注释），删掉 `wx.cloud.init`、`wx.cloud.callFunction` 分支和 `cloudReady` 即可。
2. **错误提示说人话。** `request.js:60` 不要把所有带 `errMsg` 的失败都显示成“网络异常，请稍后重试”。至少区分以下几种：合法域名未配置、超时、函数不存在（`-505005` / `FUNCTIONS_NOT_FOUND`，提示“后端接口未部署”）、其他。原始 `errMsg` 用 `console.warn` 打出来，方便排查。
3. **微信登录走网关。** 走网关时云函数拿不到平台注入的 `OPENID`，身份要靠 `wx.login` 的 code 由云函数换取，依赖 `WX_APP_ID` / `WX_APP_SECRET`（见 `cloudfunctions/common/wechat-login.js`）。核对开发版走这条路时顾客静默登录和员工微信登录都正常。
4. **部署脚本防呆。** `scripts/deploy-cloudfunctions.js` 增加一项检查：若 `.local/cloudbase/single-env-gateway.json` 存在，`--env-id` 必须与网关所属环境一致，否则拒绝部署并说明原因。
5. **文档。**
   - `AGENTS.md`“运行”第 3 条和“CloudBase 迁移入口”：写明开发版和体验版都走网关、新机器第一步要运行 `configure-cloud-preview.js`、不要往默认环境部署。
   - 开发者工具里如果网关域名没进 request 合法域名，需要 `urlCheck: false`，这一点也写上。

### 验收

- 没有 `cloud.local.js` 的机器：开发版首页直接给出明确的配置提示，不弹“网络异常”。
- 有 `cloud.local.js`：开发版首页、我的、成为代理、咨询预约、员工登录全部正常。network 面板里只有发往网关域名的请求，没有 `wx.cloud.callFunction`。

## 6. 去掉“是否整备”

### 这是什么

“是否整备”是模板里的内部字段 `refurbishment`，选项为“无需整备 / 正在整备 / 整备完成”，含义是这台机器上架前是否还要做清洁、贴膜、换件等整理。目前它会影响库存状态：

- 入库时选“正在整备”，设备会进入 `recheck`（待复检），不会直接 `in_stock`（PG 中的 `status_v := CASE WHEN attrs->>'refurbishment'='正在整备' …`，多个迁移里都有）。
- 复检时如果仍是“正在整备”，PG 拒绝复检通过（`stock_error 'P0400' 整备未完成`）；前端在 `inventory/detail.js:122` 也有同样的拦截。

去掉之后，如果某台机器暂时不想上架，入库时关闭“展示在店铺”即可，效果相同。

### 要做

1. **新迁移**（可以和第 4、5 项合并发布模板新版本）：
   - 所有分类模板的新版本删掉 `refurbishment` 字段。
   - 用 `CREATE OR REPLACE` 重写入库函数和复检函数：删掉基于 `refurbishment` 的状态分支和复检拦截，入库一律进入 `in_stock`（独立入库原来的其他条件不变）。
   - 存量数据：查出 `status='recheck'` 且 `attrs->>'refurbishment'='正在整备'` 的设备，只在报告里列出数量，**不要**自动改状态，让店员手动复检。复检拦截删掉后，这些设备可以正常复检通过。
2. **前端。**
   - 删除 `inventory/detail.js:122` 的拦截。
   - `inbound/form.js:138` 的 `rowFields` 里去掉 `'refurbishment'`。
   - `acceptance/index.wxml:43` 的文案去掉“及整备状态”。
   - `inbound/form.js:418` 入库确认弹窗里的“整备中的设备将进入复检状态，暂不可售。”删掉。
   - `mock/fields.js:23`、`mock/inbound.js:51`、`mock/test-seed.js` 同步修改。
3. 全仓搜索“整备”和 `refurbishment`，确认没有遗漏。历史迁移文件里的除外，不能改。

### 验收

- 新入库界面上看不到“是否整备”，提交后设备直接显示在库。
- 旧数据中“正在整备”的设备可以正常复检通过。

## 7. 入库价格：按价格分别填目标利润

### 现状

- 入库页（`inbound/index.wxml:60-62`）需要填写：成本、批发价、零售价、代理结算底价，另有一个“目标利润（定价辅助）”。
- 填写成本或目标利润后，会调用 `POST /pricing/suggest`（`cloudfunctions/staff-stock/index.js:23`）。服务端计算：零售价 = 成本 + 利润；批发价 = 代理底价 = 零售价 − `WHOLESALE_DISCOUNT`，且不低于成本。手动改过的价格不会被覆盖（`priceTouched`）。

### 目标

每种价格各自填写利润，自动算出对应价格；也可以直接改价格。

| 价格 | 利润输入 | 计算规则 |
|---|---|---|
| 零售价 | 零售利润 | 成本 + 零售利润 |
| 批发价（同行价） | 批发利润 | 成本 + 批发利润 |
| 代理结算底价 | 代理利润（选填，留空时等于批发利润） | 成本 + 代理利润 |

### 要做

## 8. 入库少重复劳动：“再入一台同款”和记住常用值

### 现状

- 入库成功后（`inbound/form.js:422-425`），页面会保留型号、价格和机况描述，但会清空串码、模板参数（`attributes` 重置为模板默认值）和公开照片，然后弹出“入库成功”。所以连续入同款机器时，存储容量、颜色、版本、网络锁、拆修情况这些参数每台都要重新选。
- 每次新开入库页，供应商、店保天数、保修时长、所属门店都要重新填。

### 要做

1. **再入一台同款。** 入库成功的弹窗改成两个按钮：“再入一台同款”（主按钮）和“完成”。
   - 点“再入一台同款”：保留型号、模板参数、价格、机况描述、展示/共享开关；清空串码（IMEI / SN）、电池健康、公开照片，以及所有 `type === 'image'` 的模板字段（例如收货凭证）。清空后把焦点和滚动位置定位到串码输入框，单台模式下自动拉起扫码。
   - 每台机器都可能不同的字段，用一个常量统一列出，方便以后调整，例如 `PER_UNIT_KEYS = ['battery', 'imei1', 'imei2', 'serialNo', …]`。批量模式下的 `rowFields`（`form.js:138`）也引用这份清单，保持一致。
   - 点“完成”：保持现在的行为。
   - 批量入库成功后也提供“再入一批同款”，规则相同。
2. **记住常用值。** 入库成功后，把以下字段记到本机，下次新开入库页、或者切换到同一分类的型号时自动预填。用户改了就以用户填的为准。
   - 按“员工 + 分类”分别记忆的字段：供应商 `supplier`、店保期限 `shopWarranty`、保修时长 `warrantyLength`、所属门店 `store`，以及三个分享开关。
   - 存储用 `wx.setStorageSync`，key 按 `draft.js` 中 `keyFor(user, …)` 的方式带上员工 ID，并在 `config/index.js` 的 `storageKeys` 里登记。只存 ID 和普通文本，不存成本或价格。
   - 供应商存的是 ID。预填时，如果这个供应商已经停用或不存在（字段选择器加载不到），就直接留空，不报错。
   - 当前登录员工没有供应商查看权限时，不记忆也不预填供应商。
3. **价格不记忆。** 成本和三种价格每台都可能不同，不做记忆。连续入同款时保留上一台的价格，已经由第 1 点覆盖。
4. **测试。** 给清空和保留规则写纯函数测试：输入上一台的表单，输出下一台的初始表单。

### 验收

- 连续入 3 台同型号、同配置的 iPhone：第 2、3 台只需要扫串码、填电池、拍照，其他字段都已经带好。
- 换个员工账号登录，看不到上一个员工记住的值。
