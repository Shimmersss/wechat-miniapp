## 2. 核心难点：`<page>` 不能加 class

这是整个方案的起点。原来的写法是：

```css
page {
  --c-bg: #F2F3F5;
  --c-surface: #FFFFFF;
  /* …68 个变量 */
}
```

**小程序的 `<page>` 是特殊根节点，无法动态加 class**，所以 `page{}` 上的 CSS 变量没法在运行时切换。想换主题，只能：

1. 换一整套 wxss 文件（打包体积翻倍，且切换要重启）
2. **把变量从 `page` 迁到真实元素上** ← 采用这个

### 做法

变量改挂在两个类上，由 `theme-shell` 组件包住每个页面的内容：

```css
.theme-root { --c-bg: #F2F3F5; --c-surface: #FFFFFF; /* 浅色 */ }
.theme-dark { --c-bg: #0B0C0F; --c-surface: #17191E; /* 深色，覆盖上面 */ }
```

页面结构：

```xml
<theme-shell>
  <view class="container has-tabbar">…</view>
</theme-shell>
```

切主题 = 把 `.theme-root` 换成 `.theme-root .theme-dark`，整棵子树的变量一起变。

## 3. 架构

```
utils/theme.js          主题状态：storage 读写、系统主题监听、事件广播
  ├─ get()              当前生效 'light' | 'dark'
  ├─ getPreference()    用户偏好 'system' | 'light' | 'dark'
  ├─ set(pref)          切换 + 广播 'theme:changed' + 同步原生外壳
  ├─ toggle()           浅深互切
  ├─ onChange(fn)       订阅
  └─ init()             app.js onLaunch 调用一次

components/theme-shell/ 把页面内容包进可切换的变量作用域
  └─ 自己订阅 theme:changed，主题一变自动重绘，页面无需关心

app.js                    globalData.theme，onLaunch 时 init()
styles/theme.wxss         .theme-root / .theme-dark 两套令牌
```

### 为什么用组件而不是直接加 class

页面 wxml 最外层加 `<theme-shell>` 之后，变量作用域就建立了。如果改成手动给每个页面加 class，57 个页面要改 57 次，且新增页面容易忘。

## 4. 深色主题的设计原则

**和浅色版共用同一套分层模型，只是明暗反转**：

| 层 | 浅色 | 深色 |
|---|---|---|
| L0 页面底 | `#F2F3F5` 冷灰 | `#0B0C0F` 近黑 |
| L1 卡片 | `#FFFFFF` 纯白 | `#17191E` 抬高的灰黑 |
| L2 毛玻璃 | 半透明白 | 半透明亮灰（不是白） |
| 卡内凹槽 | 比白卡更深 | 比卡片**更亮**一点 |

几个关键判断：

1. **深色下「白卡」不能真的白**，否则刺眼。用比页面底更亮的灰黑表达「抬高」。
2. **凹槽方向反转**：浅色凹槽比卡片暗，深色凹槽比卡片亮。物理直觉一致（凹进去 = 远离观察者）。
3. **投影要更重**。浅色靠淡淡的阴影就够，深色必须加深，否则层次浮不起来。
4. **语义色提亮**：红色 `#E5484D → #FF7A6E`，否则在近黑底上发闷、对比不足。
5. **环境光更饱和**：深色底上淡雅的光晕看不见，要提高到 30%～40% 透明度。

## 5. 踩过的坑（重要）

### 5.1 「墨色底 + 白字」在深色下变成白底白字

`--c-ink` 在浅色下是近黑、深色下是近白。所有 `background: var(--c-ink); color: #fff` 的组合都会在深色下失效。

**解法**：新增语义令牌 `--c-on-ink`（墨色上的文字色），浅色是 `#FFF`，深色是 `#0B0C0F`。全站替换。

### 5.2 主按钮在深色下变成刺眼白块

`btn-primary` 原本用 `--c-ink`（深色下是近白），结果主按钮成了一个大白块。

**解法**：新增 `--c-action` / `--c-action-ink`，浅色用墨色实心，深色改用品牌蓝紫 `#6E7BFF`。

### 5.3 组件样式隔离导致变量拿不到

`custom-tab-bar` 是框架渲染的，**不在页面的 `theme-shell` 里**，拿不到变量；而且组件默认 `styleIsolation: isolated`，也看不到 `app.wxss` 里 `.theme-root` 的定义。

**解法**：
- 组件 json 加 `"styleIsolation": "apply-shared"`
- tabBar 自己带一层 `<view class="tabbar-scope {{dark ? 'theme-root theme-dark' : 'theme-root'}}">`
- 用 `.tabbar-scope.theme-root { min-height: 0 }` 覆盖掉 `.theme-root` 自带的 `min-height: 100vh`，否则会盖住页面

### 5.4 图标是 SVG 图片，吃不到 CSS 变量

`<image src="...svg">` 无法通过 CSS 换色。深色主题下深色描边的图标几乎看不见。

**解法**：生成 `-light` 变体（浅色描边），tabBar 按主题切换文件名：
```xml
src="/assets/icons/{{item.icon}}{{selected ? '' : '-gray'}}{{dark ? '-light' : ''}}.svg"
```

注意基础名要对：tabBar 用的是 `home` / `grid` / `agent` / `user`，**不是** `tab-home`。生成变体时踩过这个坑。

### 5.5 `page{}` 不能用变量

`page` 是特殊根节点，拿不到 `.theme-root` 上的变量。所以 `app.wxss` 里 `page{}` 只能用字面值兜底，真实底色由 `syncNativeChrome()` 用 API 同步。

### 5.6 `<include>` 的页面不能重复包裹

`packages/staff/inbound/batch.wxml` 只是 `<include src="./index.wxml" />`，而 `index.wxml` 已经带 `theme-shell`。批量包裹脚本会给它多包一层，导致变量作用域重复。

**解法**：该文件保持只有 include，不加 theme-shell。

## 6. 加新页面时要注意

1. **wxml 最外层加 `<theme-shell>`**（全局已注册，直接用）。
2. 颜色一律用 `var(--c-*)`，不要写死。
3. 「深色底 + 浅色字」用 `--c-on-ink`，不要写 `#fff`。
4. 主操作按钮用 `.btn-primary`，会自动适配。
5. 如果用 `<image>` 引 SVG 图标且该图标有深色描边，需要准备 `-light` 变体。
6. **fixed 定位的元素**（悬浮底栏、弹层）如果不在 `theme-shell` 内，要自己带主题作用域，否则拿不到变量。

## 8. 已知限制

1. **真机未验证**。模拟器上毛玻璃和深色都正常，老安卓的 `backdrop-filter` 降级、以及深色下的实际观感需要在真机确认。
2. **深色下的图片**。商品图是浅色底的产品摄影，深色主题里会显得突兀。要彻底解决需要深色版素材，或在深色下加一层柔和的底色过渡。
3. **系统导航栏**。用 `wx.setNavigationBarColor` 同步，但自定义导航栏（`navigationStyle: custom`）的页面不响应，需要自行处理。
4. **未做「切换时过渡动画」**。目前是瞬间切换，没有淡入淡出。
5. **`--c-gold` 是历史包袱**。名字还叫 gold，实际输出墨色/浅灰。彻底清理需要改 WXML，风险大于收益，暂时保留。
