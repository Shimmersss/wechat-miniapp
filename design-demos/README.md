## 2. 设计上的几个决定

### 2.1 图标是重点，不是装饰

第一轮方案被否掉的两个原因是「颜色太素」和「黑底」。

「太素」的根源不在配色，在**图标本身**：第一版图标是单线描边 + 两色填充，48px 显示时几乎看不出内容，整个界面就靠卡片留白撑着，看起来必然空。所以第二轮把力气全花在图标上：

- 每个图标 **3～5 种颜色、4～6 个结构层次**，有主体、高光、配件、阴影面
- 深色实心填充 + 白色/浅色高光，不是描边
- 举几个例子：小店设置 = 红白条纹雨棚 + 黄招牌 + 米色墙面 + 青门 + 两扇黄窗 + 门把手；钻石 = 5 个不同色的切面 + 白色棱线 + 金色星芒；扳手 = 灰色渐变主体 + 深灰阴影面 + 红色螺丝刀柄

这套图标放在**白底容器**里效果最好。所以三个主推方案都做了同一个处理：**图标衬白色圆角方卡，彩色只出现在图标内部**，界面本身保持大面积留白或单色渐变。这也是你最初给的那几张参考图的做法——图标很花，但背景很干净。

### 2.2 三个主推方案的差异只在容器

A / D / F 用的是**完全同一套图标**，只有承载它们的卡片样式和页面底色不同：

| | 图标容器 | 页面底 | 主色 |
|---|---|---|---|
| A | 白色方卡 + 淡投影 | 纯白 / 浅灰 `#F5F5F7` | 深绿 `#1C2B20` |
| D | 果冻渐变方块（白底高光覆盖） | 橙→粉→紫渐变 | 橙粉 `#FF6B35` |
| F | 玻璃卡内白色方卡 | 莫兰迪柔光渐变 | 紫 `#6E5BD8` |

这样做的好处是**落地时不需要维护三套图标**——同一份 SVG，换容器 CSS 就能变风格。如果只做一套，选 A；要做双端，A 给员工端、D 给顾客端，共用图标。

### 2.4 视觉层次（2026-11-04 补）

第二轮稿的通病是**所有东西在同一个平面上**：页面底接近白色，卡片也是白色，分组标题直接压在底上，只能靠 1px 描边区分。参考了一个现成的门店小程序（颜色普通但层次清楚），A / D / F 统一改成三层：

| 层 | 做法 |
|---|---|
| L0 氛围底 | 状态栏和导航栏坐在品牌深色上（A 深绿 / D 橙粉 / F 暮紫），往下渐隐成**有颜色的浅灰**（`#EEF0EC` / `#F4ECE6` / `#E9EAF2`），不是白 |
| L1 白卡 | 所有分组收进白卡，去掉描边，改用更深一点的投影；「我的」页 A 用盖上来的白色底板，D/F 用独立白卡 |
| L2 卡内 | 图标方卡、浅色按钮、小数据格，比白卡再低一级 |

再加一条规则：**每页只有一个最重的色块**。库存页是数据大卡；经营页的「今日销售」改成浮在氛围底上的半透明块，其它业务卡降成白卡 + 彩色数字（D 原来是三张等重的满色卡）。预警条统一加左侧色条。

改之前的版本备份在会话临时目录，没有进版本库。实现时把渐隐底做成页面级 `background`，不要放在 `scroll` 里，否则滚动时会跟着走。

### 2.5 方案 G · 雾白层叠（2026-11-04 新增）

全白色系。白色方案最容易糊成一片，G 不靠颜色分层，靠**虚化 + 高度 + 凹凸**：

| 层 | 做法 |
|---|---|
| 光晕 | 页面顶部一团极淡的蓝/桃/紫光晕（`filter: blur(34px)`），只给上面的玻璃层提供可被虚化的内容 |
| 白卡 | 普通内容，纯白 + 浅投影 `--e1` |
| 毛玻璃 | 顶栏、悬浮底栏、每页唯一的主卡（个人卡 / 库存数据卡 / 今日数字 / 搜索框）：半透明白 + `backdrop-filter`，投影最深 `--e3` |
| 凹槽 | 卡内图标底、数据格、标签：`#F3F4F6`，比白卡更低 |

颜色只剩墨色 `#111215`（主按钮、选中态、＋号）和价格红 `#E5484D`。底栏做成悬浮玻璃胶囊，内容从它下面滑过，这是虚化效果最直观的地方。

**可运行版本（2026-11-05）**：已做成小程序演示分包 `miniprogram/packages/demo/`（首页 / 经营 / 库存 / 我的四页），不改动任何现有页面（设计理念、方法与后续开发见 [`docs/archive/方案G视觉演示交接文档.md`](../docs/archive/方案G视觉演示交接文档.md)）：

- 入口：「我的 → 开发调试 → 方案 G 视觉演示」（仅 mock 模式显示）；也可以在开发者工具里直接编译 `packages/demo/home/index`。员工三页需先切换为员工模拟身份。
- 数据全部走现有接口：首页用 `api.shop.home / units`，员工三页用 `api.dashboard.overview()`。成本、毛利由服务端按角色裁剪，拿不到时显示「无权限查看」；功能入口按权限点过滤，点进去就是现有的真实页面。
- 颜色令牌在 `styles/theme.wxss` 的 `--frost-*` 一节；毛玻璃顶栏、悬浮底栏是分包内组件 `frost-nav`、`frost-tabbar`（页面设置 `navigationStyle: custom`）。
- 图标从 `icons-v2.js` 拆成独立 SVG，放在 `packages/demo/icons/`，只保留用到的 41 个。

落地风险：小程序里 `backdrop-filter` 在老安卓 WebView 上无效，会退化成半透明白，层次会弱一档，但仍靠投影成立。另外顶栏要用自定义导航栏（`navigationStyle: custom`）才能做成毛玻璃。

### 2.3 为什么是这四个页面

四个页面覆盖了三种截然不同的信息密度：

- **我的** — 高密度功能入口（20+ 项），考验图标和网格排布
- **首页** — 商品卡片，考验图片和价格层级
- **库存数据** — 纯数据仪表盘，考验数字排版
- **经营** — 大色块 + 列表混合，考验节奏

只看「我的」一页很容易被入口密度骗过去，四个页面一起看才能判断这套视觉能不能扛住真实的业务信息量。`compare.html` 之所以只比「我的」，是因为这一页最能体现三版差异。

## 3. 已知问题与限制

诚实列一下，避免后面踩坑：

1. **玻璃拟态依赖 `backdrop-filter`**（03-enamel）。老版本安卓微信 WebView 不支持，会降级成半透明纯色块，视觉会掉一档但不会崩。上线前必须真机验证。
2. **衬线中文字体在部分安卓会回退**（04-editorial、05-boutique 用了 `Noto Serif CJK SC`）。微信小程序里系统字体不可控，如果选这两版需要准备字体子集或用图片方案。
3. **深色方案在户外强光下可读性差**（05-boutique）。这是它被弃用的主要原因之一。
4. **产品图只有两张**，其他配色靠 CSS `hue-rotate` 派生。真机上如果要求真实还原，需要补拍或补生成。
5. **假数据**。所有数字（3 台在库、¥16,650、库龄 42 天）都是编的，只为了保证版式不塌，不代表真实业务量级。
6. **无交互**。这是静态稿，只有滚动，按钮都不响应。真实交互行为以 `miniprogram/` 现有代码为准。

## 4. 如何翻成小程序

这一步还没做。真要做的时候，建议按这个顺序：

### 4.1 先动 token，不动结构

`miniprogram/styles/theme.wxss` 现在全是 CSS 变量（`--c-bg`、`--c-ink`、`--radius-lg` 等）。选中的方案里，把对应的值搬过去：

```css
/* 以 A 为例 */
page {
  --c-bg: #F5F5F7;         /* 页面底 */
  --c-surface: #FFFFFF;    /* 卡片白 */
  --c-ink: #1C2B20;        /* 主文字 / 品牌深绿 */
  --radius-lg: 20px;       /* 卡片圆角，对应稿里的 26px */
}
```

只改这一层，现有页面就会整体变色，不会破坏任何逻辑。先看效果，再决定要不要动布局。

### 4.2 图标需要转成小程序格式

`icons-v2.js` 里是 `<symbol>` + `<use>` 的写法，**微信小程序不支持 `<use href>` 跨 symbol 引用**。有两种落地方式：

**方式一（推荐，改动小）**：把 symbol 拆成独立的 `.svg` 文件放进 `miniprogram/assets/icons/`，页面里用 `<image src="/assets/icons/xxx.svg">` 引用。缺点是不能通过 CSS 变量换色——但我们的图标本来就是多彩的，不需要换色，所以没影响。

**方式二**：图标内容直接内联进 WXML（每个图标一个自定义组件）。体积会大一些，但能做交互态。

现有 `miniprogram/assets/icons/` 里有 84 个线性 SVG（`xxx.svg` / `xxx-gray.svg` / `xxx-white.svg` 三套），是旧设计。新图标是多彩的，不需要灰/白版本，命名可以简化。

### 4.3 布局改动量

- **A** — 改动最小。现有页面结构就是「白卡片 + 浅灰底」，主要是图标尺寸放大（22px → 32px）、容器从渐变块换成白色方卡、补一行状态副标题（`4 名员工`、`待转账 2 笔`）
- **D** — 中等。需要给页面加渐变背景，卡片圆角加大到 26px 左右，颜色 token 全换
- **F** — 中等偏高。玻璃卡需要 `backdrop-filter`，要加降级方案

### 4.4 别忘了几条硬约束

翻版式时不要碰这些（详见根目录 `AGENTS.md`）：

- 页面必须用 `createPage()`，不能直接 `Page()`
- 金额由服务端计算，前端不参与
- 敏感字段（成本、供应商、完整 IMEI、毛利）由服务端裁剪，前端拿到 `undefined` 时显示「无权限查看」
- 颜色、圆角、阴影只用 `theme.wxss` 里的变量

## 5. 如何重新生成截图

改了 HTML 之后，用脚本重新出图：

```bash
cd /home/smxvjv/Desktop/weixinapp/design-demos

# 默认 1800x1180 画布
./shoot.sh 01-retail-tool

# 自定义尺寸（比如四个页面并排时更高一点）
```

改图标后需要同时重跑三个主推方案：

```bash
for d in 01-retail-tool 02-candy 03-enamel; do ./shoot.sh $d; done
```
